# Migration notes — Accessible Astro (`site/`) to Starlight (`site-starlight/`)

version: 1.0
updated: 2026-08-28
status: historical — describes a one-time 2026-08-28 migration, not live site structure

**This is a historical record, not live documentation.** It describes the site as it
was the day of the Astro-to-Starlight migration (two chapters, an `astro.config.mjs`
sidebar snippet that is now stale, unchecked verification boxes referencing
long-deleted Docsify files). For the site's current structure, read
`src/content/docs/index.mdx` (the real chapter list) or the real `astro.config.mjs`
directly — not this file.

## Scaffold

```
npx degit withastro/starlight/examples/basics site-starlight
cd site-starlight && npm install
```

`npm create astro@latest` was skipped in favour of `degit` (headless-friendly, no
prompts) — the same approach the prior migration used. Starlight `^0.41.9`, Astro `^7.1.6`.
Node here is 22.21.1; install/build/dev all ran clean.

## How content was re-homed

Source of truth was the already-converted MDX/MD under `site/src/content/{lessons,reference,learning-records}/`
(NOT the original `chapters/**/*.html`). A one-shot Node script re-homed all 23 files into
Starlight's `docs` collection, restructured so URL + autogenerated sidebar reflect the book:

```
src/content/docs/
  index.mdx                                  splash homepage (ported prose + hero)
  mission.md, notes.md                       top-level pages
  01-sssf-fundamentals/{lessons,reference,learning-records}/000N-slug.{mdx,md}
  02-gates-deep-dive/{lessons,reference,learning-records}/000N-slug.{mdx,md}
  02-gates-deep-dive/resources.md            Chapter-2-only resources page
```

Counts: 7 lessons + 8 reference + 8 learning-records = 23 content pages, plus
index/mission/notes/resources = 27 authored, 28 pages built (incl. 404).

### Frontmatter rewrite (the ONLY thing that changed per file)

Old custom fields (`chapterDir`, `chapterTitle`, `chapterOrder`, `order`, `subtitle`) →
Starlight schema:

- `title` — kept verbatim.
- `subtitle` → `description` (Starlight has no visible subtitle slot; description is the
  sanctioned optional field). NOTE: this means the old subtitle line is no longer rendered
  as visible body text — it lives in page metadata only. Flag for the user if the subtitle
  should instead be surfaced on-page.
- `order` → `sidebar: { order: N }` so autogenerated groups sort 1,2,3… (verified: Ch2
  lessons render 0001→0005 in order, not alphabetical).
- chapter grouping is now expressed purely in `astro.config.mjs` `sidebar` (below).

Page BODY of all 23 files is **byte-for-byte identical** to `site/` — verified by a
body-diff script (frontmatter stripped, 0 mismatches). Import lines (`@components/...`)
were left unchanged; the alias is preserved via `tsconfig.json` `paths` (see below).

### Top-level pages

`mission.md`, `notes.md`, `resources.md` were ported from `site/src/pages/*.md`: old
`layout:` frontmatter dropped, the single leading `# H1` line removed (Starlight renders
the title as the page H1 from frontmatter — keeping the body H1 would double it), body
otherwise verbatim. `index.mdx` uses Starlight's `template: splash` with a hero whose two
actions link to the real first lesson of each chapter (NOT non-existent chapter index
pages — the bug called out in the brief was avoided). The homepage prose is ported from
`site/src/pages/index.astro`.

## Sidebar config (`astro.config.mjs`)

```js
sidebar: [
  { label: 'Mission', slug: 'mission' },
  { label: 'Notes', slug: 'notes' },
  { label: 'Chapter 1 — SSSF Fundamentals', items: [
    { label: 'Lessons',          items: [{ autogenerate: { directory: '01-sssf-fundamentals/lessons' } }] },
    { label: 'Reference',        items: [{ autogenerate: { directory: '01-sssf-fundamentals/reference' } }] },
    { label: 'Learning records', items: [{ autogenerate: { directory: '01-sssf-fundamentals/learning-records' } }] },
  ]},
  { label: 'Chapter 2 — Gates, Deep Dive', items: [
    { label: 'Lessons',          items: [{ autogenerate: { directory: '02-gates-deep-dive/lessons' } }] },
    { label: 'Reference',        items: [{ autogenerate: { directory: '02-gates-deep-dive/reference' } }] },
    { label: 'Learning records', items: [{ autogenerate: { directory: '02-gates-deep-dive/learning-records' } }] },
    { label: 'Resources', slug: '02-gates-deep-dive/resources' },
  ]},
]
```

NOTE: Starlight ≥0.39 removed `label`-on-`autogenerate`; each labelled group must wrap the
autogenerate object inside its own `items` array (done above). The brief's example used the
old shorthand and would fail to build.

## Quiz island port + verification

`Quiz.astro` and `Callout.astro` were copied verbatim into `site-starlight/src/components/`.
Their MDX imports (`@components/Quiz.astro`, `@components/Callout.astro`) resolve via a
`paths` alias added to `tsconfig.json`:

```json
"compilerOptions": { "baseUrl": ".", "paths": { "@components/*": ["src/components/*"] } }
```

The Quiz `<script>` already hooks `astro:page-load` (Starlight uses view transitions), so it
ports cleanly. Verified BOTH ways:

- **Dev** (`localhost:4322`): the lesson serves `/src/components/Quiz.astro?...type=script`,
  which contains the `wireQuiz` logic; 20 choice `<button data-index>` elements render.
- **Build** (`dist/`): Astro inlines the minified quiz module into the page HTML as
  `<script type="module">function e(e){let t=Number(e.dataset.answer)…}</script>` (found as
  inline module block #4 in the built lesson). So the quiz is live in production output, not
  just dev. (It is NOT in `_astro/*.js` — small component scripts are inlined, which is why a
  naive `_astro` grep comes up empty; this is expected Astro behaviour, not a bug.)

Callout renders (`callout-win` etc. present). Kept the existing `Callout` component rather
than converting to Starlight Asides, to avoid touching wording.
