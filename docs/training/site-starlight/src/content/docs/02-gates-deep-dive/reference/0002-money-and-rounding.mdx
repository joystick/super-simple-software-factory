## The rules

    <ol>
      <li><strong>Store money as integer cents.</strong> £10.00 is `1_000`.</li>
      <li><strong>Store percentages as integer basis points.</strong> 8.7&nbsp;% is `870`; 1&nbsp;bp = 0.01&nbsp;%.</li>
      <li><strong>Multiply first, divide once, round last.</strong></li>
      <li><strong>Round half-up</strong> — the customer gets the half cent.</li>
      <li><strong>Guard your inputs</strong> with `Number.isInteger`.</li>
    </ol>

## The shape

    
```
Math.round((amountCents * points) / 10_000)
//          └── integer ─────────┘
//                                └── one division, at the end
//         └── half-up, applied once ──────────────────────┘
```

    <p>Across 8 fractional percentages × 2,000 amounts (16,000 combinations), the float route
and the basis-point route disagreed <strong>105 times</strong>, always by one cent, always
against the customer.</p>

## Converting a percentage safely

    
```
// works for every value from 0.00 to 100.00 — checked against
// exact decimal shifting across all 10,001, zero mismatches
Math.round(Number((percent * 100).toPrecision(15)))
```

    <Callout kind="trap" label="The meta-rule">
<p>When testing numeric code, deliberately choose values that are <em>not</em> exactly
  representable in binary — 8.7, 2.675, 0.7, 3.3. Round numbers and halves like 12.5 or
  7.25 are representable, agree under both routes, and will pass a suite that is blind
  to the bug.</p>
</Callout>
