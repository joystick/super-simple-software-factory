<p>`just watch` only ever picks up issues already at `ready-for-agent` — every judgment about whether a ticket is feasible, compatible with what's already live, and compliant happens upstream of that label, interactively, inside `/triage`. This lesson covers why that judgment call stays a human's on purpose (an unattended loop making its own security/compliance calls has no one to catch it when it's wrong, the same failure shape Part C's headless-interview problem already fixed once), and the sharp edge where running `/to-spec` or `/to-tickets` interactively self-promotes a ticket past this gate by default — and what to check for before committing when that happens.</p>
