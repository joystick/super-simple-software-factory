<p>Filing a ticket is less manual than it looks — `/triage`'s own agent-brief-posting step is what creates `issues/NN-slug.md` on a local-markdown tracker — but every step in the chain has failed silently on a real repo: a file not where a skill's claim said, a status string that doesn't match what the frontier scan expects, an uncommitted change invisible to a fresh session. This lesson covers the mandatory checkpoints run after `/to-spec`, `/to-tickets`, or `/triage`: confirming the feature directory and expected files exist, that every `issues/` file's `Status:` line is parseable and one of the five canonical states, that nothing is left uncommitted, and that every `Blocked by:` reference actually resolves within the same feature.</p>
