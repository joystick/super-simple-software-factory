## Recipe — wiring a quality block


```
def test(run) -> QualityCheckResult:
    return _run(QualityCheckSpec(
        name="test",
        area="backend",
        operation="build",
        argv=["deno", "test", "--doc"],
        timeout_seconds=600,
    ), run)
```


<ol>
  <li>`argv` is a <strong>list</strong>, never a shell string.</li>
  <li>Binaries by <strong>bare name</strong> — they inherit the operator's environment.</li>
  <li><strong>Scope in the config file</strong> (`deno.json`,
      `pyproject.toml`), not in the argv.</li>
  <li><strong>Delete blocks you do not have</strong>, and drop them from
      `run_quality()`.</li>
  <li><strong>Verify by mutation.</strong> See reference 01.</li>
</ol>

## Recipe — writing an envelope gate


```
def my_gate(envelope: EnvelopeBase, run) -> GateReport:
    report = GateReport()
    for item in things_to_check:
        ok = ...
        report.check(str(item), ok, "evidence if ok, reason if not")
    return report
```


<table>
  <tr><th>Rule</th><th>Why</th></tr>
  <tr><td>one `check()` per item</td><td>a green gate then says what it verified</td></tr>
  <tr><td>record passes too</td><td>otherwise green carries no information</td></tr>
  <tr><td>`note` is written for the agent</td><td>on failure it becomes the correction text</td></tr>
  <tr><td>never build violations by hand</td><td>they are derived from failed checks</td></tr>
  <tr><td>check only the mechanically checkable</td><td>quality of judgement belongs to a reviewer</td></tr>
</table>

## What happens on failure


```
quality block fails  →  output feeds the FIX LOOP → builder repairs → gate re-runs
envelope gate fails  →  violations sent into the SAME agent session as a
                        correction, bounded by the phase's `retries`
```


<p>Both are the same idea: a failure is not an error to report, it is an <strong>input to
the next attempt</strong>.</p>

## Ways a gate gets quietly broken

<table>
  <tr><th>Hazard</th><th>Symptom</th></tr>
  <tr><td>`cmd | tee log`</td><td>exit code becomes `tee`'s — gate can never fail</td></tr>
  <tr><td>shell string argv</td><td>admits the above, plus quoting bugs</td></tr>
  <tr><td>filter matching nothing</td><td>exit 0, zero tests run</td></tr>
  <tr><td>scope in the argv</td><td>gate and local run drift apart</td></tr>
  <tr><td>path renamed</td><td>checks a directory that no longer holds the code</td></tr>
  <tr><td>gate returns a bare bool</td><td>green says nothing about what was examined</td></tr>
  <tr><td>vague `note`</td><td>the agent is told "failed" and cannot act</td></tr>
  <tr><td>gating a formatter</td><td>auto-fixable, so it turns a fix into a failure</td></tr>
  <tr><td>linting `protected_files`</td><td>a red gate no agent is permitted to fix</td></tr>
</table>

<Callout kind="trap" label="The rule that governs both families">
<p>A gate you have not watched fail is not a gate. Wiring is not finishing; writing is
  not finishing. Watching it fail is finishing.</p>
</Callout>
