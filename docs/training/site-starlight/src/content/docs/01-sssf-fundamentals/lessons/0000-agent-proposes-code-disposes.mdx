## The one idea

<p>Hand a capable model your entire job — "build the feature, test it, review it, ship it" —
and you get a machine with no seams. There is no phase boundary, so you cannot say which step
failed. There is no acceptance criterion you can name, so "done" means "the agent stopped
talking." A retry is a cold start that throws away everything the agent just learned. And the
only record is a transcript you have to read like a novel. Run it twice, get two different
systems.</p>

<p>The fix is not a cleverer prompt. It is a deliberate division of labour:</p>

<Callout kind="why" label="Agent proposes, code disposes">
<p><strong>Code owns sequencing, retries, and acceptance. The agent owns only the work inside
  one bounded phase.</strong> The model proposes work; deterministic code decides whether that
  work is acceptable before anything proceeds. Every other idea in this course falls out of
  that one line.</p>
</Callout>

## How to read this course

<ul>
  <li><strong>Lessons</strong> teach one mechanism each and end with a short quiz and a
  hands-on rep. Take them in order — each leans on the one before.</li>
  <li><strong>Reference</strong> pages are lookups you return to, not front-to-back reading.</li>
  <li><strong>Learning records</strong> are transcripts of real teaching dialogue — context,
  not practice.</li>
</ul>

<Callout kind="trap" label="The one habit that makes the rest work">
<p>The course has a rule it applies to itself: <strong>never trust a check you have not watched
  fail.</strong> A green result only means something once you have seen the thing that produced
  it go red on purpose. You will meet this on page one (L1) and in every lesson after. It is
  the whole game.</p>
</Callout>
