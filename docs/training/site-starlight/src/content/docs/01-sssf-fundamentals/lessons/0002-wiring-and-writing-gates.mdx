## The two families

<table>
  <tr><th></th><th>Quality blocks</th><th>Envelope gates</th></tr>
  <tr><td>Lives in</td><td>`adw_modules/quality.py`</td><td>`adw_modules/gates.py`</td></tr>
  <tr><td>Judges</td><td><strong>the code</strong></td><td><strong>the agent's claims</strong></td></tr>
  <tr><td>Shape</td><td>a command + exit code</td><td>`gate(envelope, run) -> GateReport`</td></tr>
  <tr><td>Runs</td><td>in a `kind="code"` phase</td><td>after every agent call, per `AgentCall`</td></tr>
  <tr><td>On failure</td><td>feeds the fix loop</td><td>sends a correction into the <strong>same</strong> agent session</td></tr>
  <tr><td>Answers</td><td>"do the tests pass?"</td><td>"did you actually write the file you said you wrote?"</td></tr>
</table>

<Callout kind="why" label="Why the second family exists">
<p>An agent's envelope is a set of claims: <em>status success, summary "added the
  endpoint", artifacts ["specs/plan.md"]</em>. Nothing about producing that JSON requires
  any of it to be true.</p>
  <p>Envelope gates are "agent proposes, code disposes" applied to the <strong>report</strong>
  rather than the code. They check what is mechanically checkable — did the file appear,
  is it non-empty, does the diff contain what was claimed. Whether the plan is any
  <em>good</em> is a reviewer's job, not a gate's.</p>
</Callout>

## Part 1 — wiring a quality block

<p>Open `adw_modules/quality.py`. Each block is a function returning a
`QualityCheckSpec`. Wiring one means replacing the placeholder argv:</p>


```
def test(run) -> QualityCheckResult:
    return _run(QualityCheckSpec(
        name="test",
        area="backend",
        operation="build",
        argv=["deno", "test", "--doc"],     # <- the whole job
        timeout_seconds=600,
    ), run)
```


### Four rules, each earned the hard way

<ol>
  <li><p><strong>`argv` is a list, never a shell string.</strong> A list means no
  shell — so no pipe can replace your exit code. `deno test | tee log` is a gate
  that can never fail, because `tee` succeeds.</p></li>
  <li><p><strong>Call binaries by bare name.</strong> These run with the operator's
  environment, so `deno` resolves the way it does in your terminal. An absolute
  path bakes your machine into the trace.</p></li>
  <li><p><strong>Scope lives in the config file, not the argv.</strong> Put includes in
  `deno.json` or `pyproject.toml`. Then the gate and your local run
  cannot disagree — which is the whole reason to have a gate.</p></li>
  <li><p><strong>Delete blocks you do not have.</strong> Remove them from the list in
  `run_quality()` too. A block running `echo` reports a check that
  never happened.</p></li>
</ol>

<Callout kind="trap" label="Then verify — lesson 1's procedure">
<p>Wiring is not finishing. Introduce a defect of the class that tool catches, confirm
  that gate goes red and the others stay green, restore. A wired gate you have not watched
  fail is still not a gate.</p>
</Callout>

## Part 2 — writing an envelope gate

<p>The whole contract is one line:</p>


```
def my_gate(envelope: EnvelopeBase, run) -> GateReport
```


<p>Build a `GateReport` by calling `report.check(item, ok, note)` once
per thing you looked at. Violations are derived from the failed checks — you never build
them yourself.</p>


```
def artifacts_exist(envelope: EnvelopeBase, run) -> GateReport:
    report = GateReport()
    for a in envelope.artifacts:
        p = Path(a)
        report.check(a, p.exists(),
                     f"exists, {_size(p)}" if p.exists()
                     else "declared artifact does not exist")
    return report
```


<p>A gate is a loop and a return. That is the entire pattern.</p>

### Why one check per item

<p>Every check is recorded whether it passed or failed, so a <em>green</em> gate says
<strong>what it verified</strong>, not merely that it passed:</p>


```
OK    justfile          exists, 4.4KB
FAIL  specs/ghost.md    declared artifact does not exist
```


<p>Compare with a gate that returns a bare boolean. Green would tell you nothing — the
exact problem from lesson 1, reproduced one level up.</p>

### The `note` is the message the agent receives

<p>On a failed check, `note` becomes the violation text, and violations are sent
back into the <strong>same agent session</strong> as a correction — bounded by the phase's
`retries`. Write notes for the agent that must act on them:</p>

<table>
  <tr><th>Poor</th><th>Good</th></tr>
  <tr><td>`"failed"`</td><td>`"declared artifact does not exist"`</td></tr>
  <tr><td>`"bad diff"`</td><td>`"claimed changed but not in the diff"`</td></tr>
</table>

### What ships already

<table>
  <tr><th>Gate</th><th>Checks</th></tr>
  <tr><td>`artifacts_exist`</td><td>every declared artifact is on disk</td></tr>
  <tr><td>`files_non_empty`</td><td>…and is not zero bytes</td></tr>
  <tr><td>`json_parses`</td><td>declared JSON actually parses</td></tr>
  <tr><td>`diff_matches_claims`</td><td>every file claimed changed exists</td></tr>
  <tr><td>`verdict_consistent`</td><td>a review's verdict agrees with its own findings</td></tr>
  <tr><td>`tests_pass(command)`</td><td>gate factory — the given command must exit 0</td></tr>
</table>

<p>Attach them per call, in the ADW:</p>


```
plan = ph.call(AgentCall(output_type=PlanOutput, prompt=prompt,
                         gates=[gates.artifacts_exist, gates.files_non_empty]))
```
