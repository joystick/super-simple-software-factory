## What a phase is

<p>A run is not one long agent session. It is a <strong>sequence of phases</strong>, and the
sequence is ordinary Python — a script you can read. Each phase is one bounded unit of work
with a name, an owner, and a lane. That is the spine the whole factory hangs on: gates
(Lesson 1–2) and envelopes (Lesson 3) are what happen <em>at the seams between phases</em>.</p>

<Callout kind="why" label="Why code owns the phase list">
<p>Hand a model your whole SDLC and you get a machine with no seams: no phase boundary, so
  you cannot say which step failed; no nameable acceptance, so "done" means "the agent
  stopped talking." Move the sequence into code and everything falls out of one line —
  <strong>phases become the unit of the trace</strong>, envelopes become the only way context
  crosses a seam, gates become the definition of done.</p>
</Callout>

## Three lanes

<p>Every phase is exactly one of three <strong>kinds</strong>, and each renders as its own
swim lane in the trace:</p>

<table>
  <tr><th>Kind</th><th>Who acts</th><th>What it is</th></tr>
  <tr><td>`engineer`</td><td>the human</td><td>the request that starts a run — your prompt, logged as the first phase</td></tr>
  <tr><td>`agent`</td><td>a model</td><td>`ph.call()`: prompt in, typed envelope out, gates verified</td></tr>
  <tr><td>`code`</td><td>deterministic Python</td><td>a step that stands on its own — a commit, a migration, running the suite</td></tr>
</table>

<Callout kind="trap" label="A code step is never buried inside an agent phase">
<p>Running the test suite is a <code>code</code> phase, not something an agent "does" and
  reports. Committing is a <code>code</code> phase. Because these stand alone in the trace,
  it shows <em>exactly</em> when code ran and when an agent was working — and a green suite
  is a fact the code observed, never a claim the agent made. This is Lesson 1's whole point,
  wired into the shape of a run.</p>
</Callout>

## The one primitive: `run.phase(...)`

<p>A phase is opened with a context manager. An ADW script is little more than a stack of
these, which is why the scripts are 40–180 lines: the logic lives in `adw_modules/`, the
script just names the sequence.</p>

```python
with run.phase(PhaseParams(
        name="build",
        kind="agent",
        owner="builder",
        description="Implement the plan; report every changed file.",
        retries=1)) as ph:
    build = ph.call(AgentCall(output_type=BuildOutput, prompt=prompt,
                              previous=plan,
                              gates=[gates.diff_matches_claims]))
```

<p>Read it as a sentence: open a phase named `build`, in the `agent` lane, owned by the
`builder`, and inside it make one call whose output must parse to `BuildOutput` and pass
`diff_matches_claims`. `previous=plan` is the prior phase's envelope — the seam from
Lesson 3, made explicit.</p>

### `ph.call()` belongs to the agent lane only

<p>The handle enforces its own lane. Calling an agent from a `code` or `engineer` phase is
a construction error, not a subtle bug:</p>

```python
def call(self, call: AgentCall) -> EnvelopeBase:
    if self.phase.params.kind != "agent":
        raise RuntimeError("ph.call() is only valid inside an agent phase")
    return agents.execute(self.run, self.phase, call)
```

### Status defaults to fail

<p>A `Phase` is born with `status="fail"` — success must be <em>earned</em> by getting to the
end of the block without an exception. If a gate raises or the JSON never parses, the phase
is already failed; nothing has to remember to mark it so.</p>

## The description is not decoration

<p>`description` is required, and it is <strong>validated at construction time</strong> — the
error fires before the phase ever opens, so it can never reach the trace half-formed:</p>

```python
# rejected — only restates the name:
PhaseParams(name="commit_plan", kind="code", owner="git",
            description="Commit the plan")

# accepted — says what it does and why:
PhaseParams(name="commit_plan", kind="code", owner="git",
            description="Commit the spec file so the plan is a reviewable artifact on its own.")
```

<Callout kind="why" label="Why the factory is this strict about one sentence">
<p>The description is the <em>only</em> sentence the trace, the console, and the phase block
  in the UI ever show about intent — everything else is ids, statuses, and timings. A
  description that echoes the name (`commit_plan: "Commit the plan"`) tells a reader nothing
  they could not already see, so it is rejected exactly like a blank one. The trace is only
  as legible as the sentences you were made to write.</p>
</Callout>
