## The machine, on one diagram

<p>A run flows left to right through phases. Agents propose inside <code>agent</code> phases;
deterministic code disposes at every seam and in every <code>code</code> phase. Everything
streams downward into the trace as it happens.</p>

## One run, traced through all of it

<p>Walk the real `b16c5c29` run (the CouponDiscount feature from L3) through the whole picture:</p>

<ol class="steps">
  <li><p><strong>engineer</strong> logs the request — "add a coupon discount." One row in
  `sessions`, one `engineer` phase.</p></li>
  <li><p><strong>planner</strong> (agent phase) proposes a spec. Its <em>envelope</em> declares
  `artifacts: [specs/…coupon-discount.md]`. Gates <code>artifacts_exist</code> and
  <code>files_non_empty</code> read those claims and pass — the seam is verified, not trusted.</p></li>
  <li><p><strong>builder</strong> (agent phase) gets `previous=plan` — the planner's envelope,
  not its chat. It reports `changed_files: [app/pricing.py, tests/test_pricing.py]`.
  <code>diff_matches_claims</code> checks each against the diff.</p></li>
  <li><p><strong>test</strong> (code phase) runs the suite. Had it failed, its result would come
  back to the builder <em>as an envelope</em> and the fix loop would correct the same session,
  up to <code>MAX_FIX_LOOPS</code> times.</p></li>
  <li><p><strong>commit</strong> (code phase) lands the work. Throughout, <em>permissions</em>
  ensured the builder touched only the repo — never <code>adws/adw_modules/</code>, its own
  grader. And every step above wrote a row into <em>sssf.db</em> while it happened.</p></li>
</ol>

<Callout kind="why" label="What you can now do that you could not at L0">
<p>Point at any factory — yours or a colleague's — open one run's trace, and narrate it seam by
  seam: which phase proposed, which gate disposed, where a correction fired, what the run was
  allowed to touch, and the one question the whole green banner still cannot answer. That
  narration <em>is</em> operating the factory.</p>
</Callout>
