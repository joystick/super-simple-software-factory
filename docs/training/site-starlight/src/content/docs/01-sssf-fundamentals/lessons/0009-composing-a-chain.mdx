## An ADW is thin on purpose

<p>A chain is an ordinary Python script. All the machinery — the runner, agents, gates,
permissions, tracer — lives in `adw_modules/`. The chain itself only names the sequence, which
is why you can read one in a minute. Here is `adw_plan_build.py`, complete but for imports:</p>

```python
def main(prompt, config="adws/adw_sssf_config/sssf.config.yaml", adw_id=None) -> int:
    cfg = agents.load_config(config)
    run = session.ensure(cfg, adw_id)                    # new run, or continue one

    with run.phase(PhaseParams(name="request", kind="engineer", owner=run.engineer,
                               description="Capture the human's request that starts the run.")) as ph:
        ph.log(input=prompt)

    with run.phase(PhaseParams(name="plan", kind="agent", owner="planner",
                               description="Turn the request into a spec the builder can follow.")) as ph:
        plan = ph.call(AgentCall(output_type=PlanOutput, prompt=prompt,
                                 gates=[gates.artifacts_exist, gates.files_non_empty]))

    with run.phase(PhaseParams(name="build", kind="agent", owner="builder",
                               description="Implement the plan; report every changed file.")) as ph:
        build = ph.call(AgentCall(output_type=BuildOutput, prompt=prompt, previous=plan,
                                  gates=[gates.diff_matches_claims]))

    with run.phase(PhaseParams(name="commit", kind="code", owner="git",
                               description="Commit the build once its claims are verified.")) as ph:
        ph.log(sha=git_helper.commit_all(build.commit_message))

    return run.finish()
```

<p>Every idea from Lessons 3–5 is visible here: the `engineer` lane opens it, agent phases
carry an `output_type` and `gates`, `previous=plan` is the envelope crossing the seam, and the
commit is a `code` phase that stands alone.</p>

## The starter chains

<p>You rarely start blank. Twelve chains ship; you copy the nearest and adjust:</p>

<table>
  <tr><th>Chain</th><th>Reach for it when</th></tr>
  <tr><td>`adw_prompt`</td><td>one agent, one prompt</td></tr>
  <tr><td>`adw_scout`</td><td>read-only recon, nothing changes</td></tr>
  <tr><td>`adw_plan` / `adw_build`</td><td>you want only the spec, or only the code</td></tr>
  <tr><td>`adw_quality`</td><td>lint/typecheck/build, no agents at all</td></tr>
  <tr><td>`adw_build_test`</td><td>there is a suite to satisfy (bounded fix loop)</td></tr>
  <tr><td>`adw_plan_build_test`</td><td>the standard chain</td></tr>
  <tr><td>`adw_simple_sdlc`</td><td>plan → build → test → review → document</td></tr>
</table>

<p>That is the shortlist you will actually reach for. The rest of the twelve —
`adw_build_review`, `adw_document`, `adw_plan_build`, `adw_plan_build_test_quality` — are
narrower variants of the same names above with one phase added or removed;
`ls adws/adw_*.py` in the Python playground repo lists all twelve if you want the full set.</p>

## Bounded loops are just Python

<p>The fix loop from Lesson 5 is not a framework feature — it is a `for` loop in the chain,
capped by a constant you can see:</p>

```python
for i in range(1, MAX_FIX_LOOPS + 1):
    with run.phase(PhaseParams(name=f"test_{i}", kind="code", owner="quality", ...)) as ph:
        test = quality.run_tests(run)
    if test.passed:
        break
    with run.phase(PhaseParams(name=f"fix_{i}", kind="agent", owner="builder", retries=1, ...)) as ph:
        ph.call(AgentCall(output_type=BuildOutput, prompt=fix_prompt,
                          previous=quality.as_envelope(test, "tests"), gates=[gates.diff_matches_claims]))
```

## Two questions, two phases

<p>The fuller chains separate two things a beginner conflates. `adw_simple_sdlc` runs both a
test phase and a reviewer phase, because they ask different questions:</p>

<table>
  <tr><th>Phase</th><th>Asks</th><th>Against</th></tr>
  <tr><td>`code(test)`</td><td>"does it run?"</td><td>the suite</td></tr>
  <tr><td>`agent(reviewer)`</td><td>"is this what was asked for?"</td><td>the plan</td></tr>
</table>

<p>Neither can answer the other's question. A suite that passes says nothing about whether the
feature is the one requested; an approving review says nothing about whether the code runs.</p>

## A green phase does not make a green run

<Callout kind="why" label="Acceptance is a run-level fact, decided at finish">
<p>`run.finish(accepted=..., reason=...)` is where a run's verdict is set — and it is separate
  from whether the phases passed. A fix loop can exhaust its three attempts with the last
  builder phase itself "green," yet `test.passed` is still false, so the run must fail. The
  chain calls `run.finish(accepted=test.passed, reason="the suite still failed after 3
  attempts")`. Phases succeeding is necessary; it is not sufficient.</p>
</Callout>

<Callout kind="trap" label="A phase without a gate is unchecked work, faster">
<p>The moment you add an agent phase, ask what verifies its envelope. An agent phase with an
  empty `gates=[]` produces a report nobody checked — the Lesson 1 problem, re-introduced by
  omission. Composing a chain is as much about attaching the right gates as ordering the
  phases.</p>
</Callout>
