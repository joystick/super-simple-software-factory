<p>A plan built without first interrogating the codebase's real boundaries — what's actually load-bearing, what's already implemented, what a `protected_files` list should exclude — is a plan built on guesses, and guesses compound across every phase that follows it. This lesson covers the interrogate-before-plan discipline: the questions worth forcing answered in an interactive session before you let a planner phase run unattended, and why doing this once, on purpose, up front costs far less than discovering the gap three phases deep in a failed build.</p>
