# Plan — Audio-narrated lectures

Tracer-bullet slices: get one lesson narrating + syncing end to end before scaling to all.
See [PRD](2026-08-28-audio-lectures-prd.md).

## Phase 1 — Testable core (TDD)
- [ ] `scripts/audio/extract-sections.mjs` — `extractSections(html)` pure fn; `node:test` first (RED), then implement (GREEN).
- [ ] `scripts/audio/cue-map.mjs` — `buildCueMap(durations)` pure fn; test-first.
- [ ] Tests cover: code/pre stripped, callout text included, headings become section titles, ids preserved, empty/degenerate input.

## Phase 2 — Build pipeline (one lesson)
- [ ] Voice detection helper (best premium en_* else Samantha).
- [ ] `scripts/audio/build-audio.mjs`: build the site → for a target slug, read `dist` HTML → extractSections → `say` per section → `afinfo` duration → `ffmpeg` concat → `public/audio/<slug>.m4a` + `<slug>.json`.
- [ ] Run on Lesson 1; sanity-check the m4a plays and the manifest cue starts look right.

## Phase 3 — Player component
- [ ] `AudioLecture.astro`: fetch `/audio/<slug>.json` for the current page; render nothing if missing.
- [ ] Transport UI: play/pause, prev/next (cue boundaries), seek scrubber, elapsed/total, volume; data-testid hooks.
- [ ] Sync: on `timeupdate`, highlight the matching `starlight-toc a[href="#id"]`; clicking a TOC entry seeks; reduced-motion = highlight only.
- [ ] Mount once per doc page via a Starlight component override (Sidebar/PageTitle/Header slot — whichever cleanly renders on every doc page); theme-aware.

## Phase 4 — Scale + wire
- [ ] Generate audio for all lessons (both chapters) + mission/notes; add a `just audio` recipe.
- [ ] Commit `public/audio/**` (m4a + json).

## Phase 5 — Verify (Playwright) + judgement
- [x] Playwright: play → correct TOC highlight; next/prev move highlight + audio; TOC-click seeks; both themes; mobile width.
- [x] Usability judgement: per-lesson-file + section sync feels good (podcast-style transport + live TOC highlight). Keep it.
- [x] `/code-review` pass on the new code; apply fixes.

### Post-ship tweaks
- **Bigger inter-sentence pauses** — first done via macOS `say` `[[slnc]]`; now via Piper's native `--sentence-silence 0.5`.
- **Switched TTS engine to Piper (neural), via Docker.** macOS `say`/Daniel replaced with Piper for far more natural narration. The macOS Piper wheels are broken (hardcoded espeak data path) and the standalone binary is missing dylibs; the standalone binary and `pocket-tts` were both dead ends. Piper's **Linux** wheels work perfectly, so generation runs in a small Docker image (`scripts/audio/piper.Dockerfile`, voices baked in). `pocket-tts` rejected (wanted to upgrade 15 core brew packages incl. gcc/llvm/rust/pytorch).
- **Two voices, learner-selectable** — every lesson is rendered in **amy** (US female) and **ryan** (US male, high-quality). Manifest is multi-voice; the player has a voice toggle that persists the choice (localStorage) and reloads the right cue map. (No Siri/Samantha voice exists for Piper — Apple-proprietary; amy is the warm-female stand-in.)
- Removed `pauses.mjs`/test (Piper handles pauses natively).
- **Audio is git-ignored** (reverses the PRD's "commit to repo" call). `public/audio/` (both .m4a and manifests) is build output regenerated by `just audio`; a deploy must run `just audio-image` (once) + `just build` + `just audio`. Keeps the repo light; ~118 MB stays out of git going forward. (Old audio blobs remain in history — purge with git-filter-repo/BFG if desired.)

### Code-review outcomes (applied)
- **Fixed** — intro cue id was hard-coded `intro` but the TOC "Overview" links to `#_top`; intro now uses `_top` so it syncs and is seekable.
- **Fixed** — a heading whose only content was a skipped block (diagram/quiz/code) was dropped, leaving no cue; every heading now keeps a title-only cue so its "On this page" entry still highlights.
- **Fixed** — the player rendered on every page (404 manifest fetch on non-lesson routes); now rendered only on lesson pages.
- **Fixed** — temp dir leaked on a `say`/`ffmpeg` error; wrapped in try/finally. Total-time label now taken from the true encoded m4a length.
- **Fixed earlier** — Expressive Code blocks were read as literal markup; extractor now skips any block containing a `<pre>` (regression test added).
- **Noted, not changed** — cue starts are summed raw-clip durations vs the AAC file's timeline: a single ~50ms constant priming offset, imperceptible at section granularity. Voice-name suffix `(Premium)` is the string `say -v` expects; only relevant if a premium voice is installed (none here).
