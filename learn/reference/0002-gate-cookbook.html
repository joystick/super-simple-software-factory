Gate cookbook

Two families, the recipes for each, and the ways they get quietly broken.

Recipe — wiring a quality block

def test(run) -> QualityCheckResult:
    return _run(QualityCheckSpec(
        name="test",
        area="backend",
        operation="build",
        argv=["deno", "test", "--doc"],
        timeout_seconds=600,
    ), run)
  1. argv is a list, never a shell string.
  2. Binaries by bare name — they inherit the operator's environment.
  3. Scope in the config file (deno.json, pyproject.toml), not in the argv.
  4. Delete blocks you do not have, and drop them from run_quality().
  5. Verify by mutation. See reference 01.

Recipe — writing an envelope gate

def my_gate(envelope: EnvelopeBase, run) -> GateReport:
    report = GateReport()
    for item in things_to_check:
        ok = ...
        report.check(str(item), ok, "evidence if ok, reason if not")
    return report

What happens on failure

quality block fails  →  output feeds the FIX LOOP → builder repairs → gate re-runs
envelope gate fails  →  violations sent into the SAME agent session as a
                        correction, bounded by the phase's `retries`

Both are the same idea: a failure is not an error to report, it is an input to the next attempt.

linting protected_filesa red gate no agent is permitted to fix
The rule that governs both families

A gate you have not watched fail is not a gate. Wiring is not finishing; writing is not finishing. Watching it fail is finishing.
